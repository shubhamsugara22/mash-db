======================================================
ORDER BY + LIMIT/OFFSET FEATURE TEST CASES
======================================================

Test Setup: Insert test data
- INSERT 3 charlie charlie@example.com
- INSERT 1 alice alice@example.com
- INSERT 5 eve eve@example.com
- INSERT 2 bob bob@example.com
- INSERT 4 diana diana@example.com

======================================================
Test 1: ORDER BY ASC (default)
======================================================
Query: SELECT * ORDER BY id
Expected Result: 
(1, alice, alice@example.com)
(2, bob, bob@example.com)
(3, charlie, charlie@example.com)
(4, diana, diana@example.com)
(5, eve, eve@example.com)

Query: SELECT * ORDER BY username
Expected Result: (sorted alphabetically by username)
(1, alice, alice@example.com)
(2, bob, bob@example.com)
(3, charlie, charlie@example.com)
(4, diana, diana@example.com)
(5, eve, eve@example.com)

======================================================
Test 2: ORDER BY DESC (descending)
======================================================
Query: SELECT * ORDER BY id DESC
Expected Result:
(5, eve, eve@example.com)
(4, diana, diana@example.com)
(3, charlie, charlie@example.com)
(2, bob, bob@example.com)
(1, alice, alice@example.com)

Query: SELECT * ORDER BY username DESC
Expected Result: (reverse alphabetical order)
(5, eve, eve@example.com)
(4, diana, diana@example.com)
(3, charlie, charlie@example.com)
(2, bob, bob@example.com)
(1, alice, alice@example.com)

======================================================
Test 3: LIMIT (returns first N rows)
======================================================
Query: SELECT * ORDER BY id LIMIT 3
Expected Result: (first 3 rows in id order)
(1, alice, alice@example.com)
(2, bob, bob@example.com)
(3, charlie, charlie@example.com)

Query: SELECT * ORDER BY id DESC LIMIT 2
Expected Result: (first 2 rows in reverse id order)
(5, eve, eve@example.com)
(4, diana, diana@example.com)

======================================================
Test 4: OFFSET (skip first N rows)
======================================================
Query: SELECT * ORDER BY id LIMIT 2 OFFSET 1
Expected Result: (skip 1 row, return next 2)
(2, bob, bob@example.com)
(3, charlie, charlie@example.com)

Query: SELECT * ORDER BY id LIMIT 3 OFFSET 2
Expected Result: (skip 2 rows, return next 3)
(3, charlie, charlie@example.com)
(4, diana, diana@example.com)
(5, eve, eve@example.com)

======================================================
Test 5: Combined ORDER BY + WHERE + LIMIT/OFFSET
======================================================
Query: SELECT * WHERE id > 2 ORDER BY username ASC LIMIT 2
Expected Result: (filter where id > 2, sort by username, limit 2)
(3, charlie, charlie@example.com)
(4, diana, diana@example.com)

Query: SELECT id, username WHERE id < 5 ORDER BY id DESC LIMIT 2 OFFSET 1
Expected Result: (filter id < 5, reverse order, skip 1, limit 2)
(3, charlie)
(2, bob)

======================================================
Test 6: Pagination Example
======================================================
Query: SELECT * ORDER BY username ASC LIMIT 2 OFFSET 0
Expected Result: (page 1)
(1, alice, alice@example.com)
(2, bob, bob@example.com)

Query: SELECT * ORDER BY username ASC LIMIT 2 OFFSET 2
Expected Result: (page 2)
(3, charlie, charlie@example.com)
(4, diana, diana@example.com)

Query: SELECT * ORDER BY username ASC LIMIT 2 OFFSET 4
Expected Result: (page 3)
(5, eve, eve@example.com)

======================================================
Implementation Notes:
======================================================
1. ORDER BY Column: Sort by id, username, or email
2. ASC/DESC: Ascending (default) or Descending order
3. LIMIT N: Return at most N rows
4. OFFSET N: Skip N rows before returning results
5. All can be combined: ORDER BY + WHERE + LIMIT + OFFSET
6. Order of precedence: WHERE filtering → ORDER BY sorting → OFFSET skipping → LIMIT limiting
