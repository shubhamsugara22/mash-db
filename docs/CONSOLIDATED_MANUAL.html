Quick Start Guide

1. Build the Project

cargo build --release

2. Run the Database

./target/release/Mash_db.exe

3. Your First Commands

db > CREATE TABLE users (id, username, email)
Table created.

db > INSERT INTO users VALUES (1, 'alice', 'alice@example.com')
Executed.

db > SELECT * FROM users
(1, alice, alice@example.com)
Executed.

db > .exit
Bye!

Basic Commands

INSERT - Add Data

-- Simple format
INSERT 1 alice alice@example.com

-- Named columns format
INSERT INTO products VALUES (1, 'Widget', '19.99', '100', 'Tools')

SELECT - Retrieve Data

-- All columns
SELECT * FROM users

-- With WHERE clause
SELECT * FROM products WHERE price > '20'

-- With ORDER BY
SELECT * FROM products ORDER BY name DESC

-- With LIMIT
SELECT * FROM products LIMIT 10

UPDATE - Modify Data

UPDATE products SET price = '25.00' WHERE id = 1

DELETE - Remove Data

-- Delete by ID
DELETE WHERE id = 1

-- Delete by condition
DELETE WHERE category = 'Tools'

-- Delete all
DELETE ALL

Advanced Features

Dynamic Schemas

Each table can have unlimited custom columns:

CREATE TABLE products (id, name, price, stock, category)
CREATE TABLE stores (id, name, city, manager, year_opened)

B-Tree Indexing

Automatic indexes on (id, username, email) for fast lookups:

-- Fast (O(log n)) - uses index
SELECT * FROM users WHERE id = 5

-- Slower (O(n)) - full scan
SELECT * FROM products WHERE category = 'Tools'

Data Persistence

  • Automatic save after each operation
  • Binary JSON-compatible format
  • One file per table (*.json)

Architecture Overview

Troubleshooting

Common Issues

Duplicate ID error

Cause: ID already exists in table. Solution: Use a different ID number.

Table not found error

Cause: Table does not exist. Solution: Check table name with SHOW TABLES.

No results from SELECT

Cause: Table is empty or WHERE filter is too restrictive. Solution: Try SELECT * without WHERE.

Slow queries

Cause: Querying unindexed column. Solution: Use id, username, or email for fast lookups.

Data Backup

cp backup/*.json .
